# 证据与风险规则（evidence-and-risk-rules）

## 1. 三级预警与证据强度

预警级别（I 高 / II 中 / III 低）表示**复核优先级**；证据强度（A/B/C/D）表示**证据可靠性**；
两者分列，不得互相替代。

| 强度 | 定义 | 示例 |
|---|---|---|
| A | 原始官方/原始文件 | 标书原文提取、文件属性原文 |
| B | 官方页面或授权导出 | 官方网站查询页、SRM 授权导出、正式 API 返回 |
| C | 经验证的第三方公开信息 | 人工导入截图（有 meta）、第三方资料 |
| D | 自动推断或待人工确认 | 覆盖缺口、低置信度线索 |

**强制上限**：任何 D 级证据 ≤ III 级；任何主体未确认 ≤ III 级；
任何仅依赖名称模糊匹配的关联 ≤ III 级（人工确认主体前）。

## 2. 规则清单（rules/risk-rules.yaml，版本化）

| 规则 | 含义 | 默认级别 | 说明 |
|---|---|---|---|
| ID-001 | 不同投标人统一社会信用代码相同 | I | 先核对来源；精确匹配，不允许模糊 |
| ID-002 | 法人/授权代表证件受控摘要相同 | I | 摘要一致即同一证件号；含 ≥2 条证据；必须人工复核 |
| ID-003 | 电话、邮箱、联系人、地址完全一致 | II | 手机以受控摘要比对 |
| ID-003W | 同名人名 / 同一行政区划地址 / 名称相近 | III | 候选线索，禁止单独认定 |
| META-001 | 非通用元数据同源（作者/公司/标题/类别/自定义属性等） | II* | *单项有限辨识字段 III；≥2 个独立字段 II |
| META-002 | 明确的设备唯一标识重复 | I | 仅限文件中实际读出的序列号/唯一 ID；I 级候选仍需人工核验 |
| META-003 | 弱线索（编辑工具一致、创建时间相近） | III | 不得单独用于否决性判断 |
| OWN-001 | 同一截点的共同控制、共同股东或明确股权关联 | II | 历史关系（未覆盖投标截止日）降 III 并注明日期 |
| JUD-001 | 已确认主体的司法经营风险记录 | II | 主体未确认 → III 且不归属 |
| DIS-003 | 政府采购网失信记录（规则版本 1.1.0 起，信用中国/军采渠道已移除） | II | 主体未确认 → III 且不归属 |
| COV-001 | 外部来源未查/失败/受限/主体未确认 | III | 证据强度 D；不产生“无风险”结论 |

## 3. 文件属性三类信息（extract_metadata.py）

| 类别 | 例子 | 可作出的结论 |
|---|---|---|
| 唯一标识（unique_id） | 明确相同的设备序列号、文件内部唯一 ID 且来源可信 | I 级候选线索（META-002），仍需人工核验原件与生成链路 |
| 有限辨识（limited_identifying） | 扫描仪型号、同一自定义作者名、相同内部路径 | 单项 III；≥2 个独立字段叠加 II。Make/Model/Software 视为一个“设备身份”字段 |
| 常见或可轻易修改（common_or_modifiable） | Adobe/WPS、空白作者、创建时间、PDF 版本 | 仅 III 级线索（META-003），不得单独提升 |

“设备码”只能指从文件中实际读出的序列号/唯一 ID，**不能由相同设备型号推断**。
图像相似度/模板相似度如未来增加，必须写明算法版本、阈值、样本与误报限制，
默认只输出 III 级候选。标题/主题含项目名称的值不视为有效同源线索（同项目投标的正常现象）。

## 4. 交叉匹配矩阵（normalize_and_match.py）

| 字段 | 精确匹配 | 模糊匹配 | 默认最高预警 |
|---|---|---|---|
| 统一社会信用代码 | 同一法人强证据（先核对来源） | 不允许 | I |
| 法人/授权代表证件摘要 | 相同且来源清晰 | 不允许 | I |
| 法定代表人、股东 | 同名后必须结合主体或公开股权证据 | 名称相似仅候选 | II |
| 电话、邮箱、联系人 | 完全一致（手机按摘要） | 不使用尾号或局部相似 | II |
| 地址 | 精确到门牌/房间且结合其他字段 | 仅行政区划 | II / III |
| 公司简称、名称 | 仅作检索和候选 | 允许但待确认 | III |

股权关系保存为有向图：`股东/控制人 → 被投资企业`（含比例、关系日期、来源、主体确认状态）。
只有能在投标截止日同一截点确认的直接/间接控制、共同股东或明确人员重合，才输出 II 级以上；
历史股东、名称相近企业、未验证第三方图谱只能 III 级或待确认。

## 5. 失信记录的有效性与相关性

对每条 DIS-* 记录分别输出：

1. **原始记录事实**（当事人、行为、文号、日期）；
2. **记录载明期间**（effective_from/to，来自记录本身）；
3. **与投标截止日的关系**：期间覆盖截止日 → “可能处于有效期内（以处罚决定原文为准）”；
   已届满/未开始 → 如实说明；无日期或无截止日 → “无法判断”；
4. **与采购文件资格条款的匹配结果**：`procurement_rules_source = unspecified` 时只能写
   “存在记录，资格影响待采购人确认”，并列入尚缺材料。

## 6. 模型的角色边界

模型可以：字段候选提取、风险摘要转写、待核实说明。
模型不可以：修改规则输出、调整预警等级/证据强度、把无证据断言写入 findings、
把 blocked/failed/not_queried 写成“无风险”。
